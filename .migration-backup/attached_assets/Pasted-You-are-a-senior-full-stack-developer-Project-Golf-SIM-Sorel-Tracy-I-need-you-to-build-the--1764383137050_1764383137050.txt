You are a senior full-stack developer.  
Project: “Golf SIM Sorel-Tracy” — I need you to build the authentication and security infrastructure before doing booking/calendar logic.  

Requirements:

1. Authentication & session management  
   - Use cookie-based sessions (not localStorage).  
   - Session cookies must have these attributes: HttpOnly, Secure, SameSite=“Strict” or “Lax”, and reasonable expiry.  
   - Do not expose any secret tokens or session data to client-side JS.

2. Secure API routes & protected routes  
   - Any API route that modifies data (bookings, admin tasks, calendar sync) must verify session / user role (admin) before proceeding.  
   - If user is not authenticated or not admin, return 401 or 403.  

3. Input validation & sanitisation  
   - Validate and sanitize all incoming user data (names, emails, date/time, comments, etc.)  
   - Do not use any unsanitized user input in HTML or database queries without cleaning.  

4. CSRF protection for state-changing requests  
   - Use CSRF tokens or ensure SameSite + secure cookies to minimize CSRF risk.  
   - Ensure POST/PUT/DELETE requests that change server state are protected.  

5. Use HTTPS / enforce secure transport  
   - On production, enforce HTTPS.  
   - Set cookie Secure attribute so cookies only travel over HTTPS to prevent interception.  

6. Security headers & Content Security Policy (CSP)  
   - Set up HTTP response headers for security: e.g. Content-Security-Policy restricting allowed sources (scripts, styles, images, fonts).  
   - Optionally set other headers: X-Frame-Options / frame-ancestors to avoid clickjacking, etc.  

7. Proper storage of secrets & credentials  
   - Store any secrets / keys / credentials (session secret, OAuth keys, API keys) in environment variables — never in client code or source files committed to repo.  
   - On server only.  

8. Minimum permissions & principle of least privilege  
   - Limit what each part of the backend can do. E.g. database user with least privileges; calendar-sync only uses needed scopes.  
   - Avoid overly broad permissions.  

9. Error handling & logging without leaking sensitive info  
   - Catch errors, avoid sending stack-traces or sensitive info to client.  
   - Log internally securely (but don’t expose secrets).  

10. Optional but recommended: rate-limiting & brute-force protection on login / booking endpoints  
   - Prevent abuse: e.g. limit number of booking attempts per IP / per minute, limit login attempts.  

Deliverable:  
- Configuration and code in Next.js / Node.js set up with all above security measures.  
- Example of protected API route + session handling + secure cookie.  
- Sample `.env.example` listing required env vars (session secret, etc.)  
- README explaining how to deploy securely (https, environment variables, etc.)
